# 🚧 能力边界与三个天花板

在开始使用这套工作流之前，了解它的**能力边界**至关重要。这能帮助你建立合理的预期，避免把时间花在“AI 做不到”的事情上。

> **核心观点：** 这套工作流的核心价值是 **“让以前做不到的事变得可以做”**，而不是 **“让 AI 变成万能的神”**。

## ✅ 适合做什么

根据已有实践，这套工作流在以下场景中表现最为出色：

### ① 模型查询与分析

通过自然语言快速获取模型信息，无需手动翻阅属性面板。

| 示例指令 | 实际效果 |
| :--- | :--- |
| “找到所有类型为‘混凝土-200mm’的墙，高亮选中它们” | 按类别、族名称、参数值筛选图元 |
| “第一层有多少根高度大于 3 米的柱子？” | 统计图元数量，按类别或楼层汇总 |
| “获取选中元素的 ID、类别、标高和所有参数值” | 输出元素的详细信息 |

### ② 规则明确的批量操作

当需求满足以下条件时，AI 的执行效率是人工的数十倍到上百倍：

- **规则可以用语言描述清楚**（如“把所有 KL 前缀的梁按截面尺寸合并”）
- **操作对象可以被筛选条件精确定义**（如“选中视图中所有 400x800 的梁”）
- **操作本身是 Revit API 支持的标准修改**（如修改参数、替换类型、删除元素）

> 这是将 **“不可能按时完成”** 变为 **“数十分钟搞定”** 的关键差异。

### ③ 缺乏现成工具的小众需求

传统工作流中，“没有现成插件”往往意味着项目卡死或需要高成本定制开发。而 AI 工作流的优势在于：

> **只要你能用语言描述清楚“从什么数据、经过什么处理、得到什么结果”，AI 就能在数分钟内组合出解决方案。**

不需要等待插件更新，不需要说服开发团队排期。

### ④ 能力普及

这套工作流做不到“让每个人都变成 Revit 专家”——它能做到的是：

> **把专家能力通过 AI 放大，让非专家也能调用。**

一个懂 Revit 基本原理但不会 Dynamo 的工程师，通过自然语言描述，可以完成原本需要数天手动工作量的任务。

## 🚫 三个天花板（做不到什么）

以下三项受限于 Revit 的底层架构和 AI 的技术特性，是这套工作流**无法逾越的硬边界**。

### 天花板一：一句话翻模

> **“帮我生成一栋完整的楼。”——做不到。**

**本质原因：Revit 是“关系型数据库 + 图形化前端”，不是“几何建模软件”。**

| 对比维度 | Blender / Rhino 等建模软件 | Revit / Bentley 等 BIM 软件 |
| :--- | :--- | :--- |
| **本质** | 画图工具，只管形状 | 一个“带图形的数据库”——几何 + 信息 + 关系 |
| **创建元素时** | “这里有一个立方体” | “这里有一面墙，类型是‘混凝土-200mm’，高度 3m，属于结构用途，材质 C30，标高在楼层 1...” |
| **能创建什么** | 任何形状，无限制 | 只能创建 Revit 预定义的 **82 个内建类别** 里的东西 |
| **信息附带** | 只包含几何信息 | 几何信息 + 参数信息 + 关联信息（这面墙是哪个房间的边界？） |
| **修改元素时** | 直接拖拽 | 可能触发连锁反应（删除墙 → 附着在墙上的门窗也被删除） |

**通俗比喻：**

> Revit 就像一本 **“乐高说明书”**——它告诉你只有这些零件（墙、门、窗、柱...），你必须用规定的零件来搭。你不能自己造一个乐高没有的零件。
>
> Blender 就像一桶 **“橡皮泥”**——你想捏什么形状都行。

**所以：**

- ✅ 一句话生成“几何体”是可行的（在 Blender 里）
- ❌ 一句话生成“Revit 模型”是不现实的——因为 Revit 模型需要的不是“形状描述”，而是 **“完整的信息定义”**，这需要的信息量，一句话不可能装下。

### 天花板二：超复杂单步操作

> **“帮我把这栋楼全部翻模。”——无法一步完成。**

**本质原因：Revit 的“单次外部事件”机制限制了单次操作的复杂度。**

| 限制 | 说明 |
| :--- | :--- |
| **单线程** | Revit 一次只能处理一个外部事件，不能并行执行多个任务 |
| **事务超时** | 单个事务执行超过 2~3 秒，Revit 界面会“冻住” |
| **原子回滚** | 如果中途出错，整个事务全部回滚——不会出现“改了一半”的状态 |

**所以：**

- ✅ 把复杂任务拆成多个子任务（如“生成轴网 → 生成标高 → 生成墙 → 生成楼板”），AI 可以依次执行
- ❌ 让 AI “一次搞定所有事”——Revit 不允许，AI 也做不到

> 💡 **正确做法：** 像指挥施工一样，把大工程拆解成一个个小工序，让 AI 逐步完成。这也是 `Skills` 发挥作用的地方——把常复用的小工序封装成技能，一键触发。

### 天花板三：模糊描述精准执行

> **“让这面墙变成承重墙。”——AI 可能会猜错。**

**本质原因：自然语言的“自然”不等于“精确”，而 Revit 需要精确的指令。**

| 用户原话 | AI 的理解难度 | 执行过程 | 耗时 | 成功率 |
| :--- | :--- | :--- | :--- | :--- |
| **“让这面墙变成承重墙”**（模糊） | 高——包含多层隐含逻辑 | ① 搜索“承重墙”的定义 → ② 尝试修改 → ③ 报错 → ④ 排查原因 → ⑤ 重新执行 | 30 秒 ~ 1 分钟 | ~70% |
| **“把选中墙的 Structural 参数改成 true”**（精确） | 低——指令明确到具体参数和值 | ① 直接定位 Structural 参数 → ② 修改为 true → ③ 完成 | 2~3 秒 | ~100% |

**为什么模糊指令会导致问题？**

AI 在面对模糊指令时，需要自己“猜”中间步骤：
- 是先改 A 再改 B，还是直接改 C？
- “承重墙”对应的参数名是 `Structural`、`LoadBearing` 还是 `StructuralUsage`？
- 这个参数是只读的吗？需要先解锁吗？

**而精确指令直接告诉 AI：**
- 哪个参数（Structural）
- 改成什么值（true）
- 参数类型（布尔型）

**所以：**

- ✅ 懂原理的人用起来觉得强大——因为他知道怎么给 AI 下精确指令
- ❌ 不懂原理的人用起来觉得鸡肋——因为他模糊的指令让 AI 找不到北

> 💡 **这就是本项目 `Rules` 存在的核心原因：** 把“如何给出精确指令”的规则固化成 AI 的行为准则，让 AI 即使面对模糊需求，也能按照标准流程去追问和拆解，而不是自己瞎猜。

## 📊 总结

| 场景 | 是否适合本工作流 | 建议 |
| :--- | :--- | :--- |
| **查询模型信息** | ✅ 非常适合 | 直接提问，AI 会返回数据 |
| **规则明确的批量修改** | ✅ 非常适合 | 描述清楚“改什么、改成什么”即可 |
| **小众/无现成插件的需求** | ✅ 非常适合 | 描述清楚“从什么数据→经过什么处理→得到什么结果” |
| **一句话翻模** | ❌ 不适合 | 拆解为多个子任务，逐步完成 |
| **超复杂单步操作** | ⚠️ 需拆分 | 拆成多个小工序，用 Skills 封装复用 |
| **完全模糊的描述** | ⚠️ 效果不佳 | 先学习 Revit 的基本概念，提高提问精度 |
