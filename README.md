基于MCP协议的Revit AI智能体工作流实践应用

> 用自然语言对话直接操作 Revit —— 让以前做不到的事变得可以做。

## 真实场景案例

以下案例均来自实践，展示了这套工作流在真实项目中的核心价值：**将“不可能按时完成”变为“数十分钟内解决”**。

### 案例一：批量合并梁类型（效率大幅提升）

> **背景：** 某体育中心Revit建模项目，1658根梁实例对应494个类型名称，每个类型名都附带了图纸编号（如`KL1(5)-200x800`），甲方觉得不好管理，临时要求BIM团队快速响应，将项目族类型按截面尺寸合并（如`KL-200x800`）。

- **传统手动建模方式**：需要先手动统计新类型避免遗漏，再手动创建100多个新类型，再逐一核对并替换1658条梁对应的族类型。保守估计需要 **3~5天**，且极易漏改。
- **Dynamo/编程方式**：编写Dynamo脚本或简易二开约需 **1~2天**，但对土木专业工程师的编程能力要求高，或依赖外部开发能力。
- **本工作流方案**：通过自然语言描述规则，AI自动执行。从编写提示词到执行完成，总计耗时 **25分钟**，且无遗漏。

### 案例二：即时响应特殊需求（避免项目卡死）

> **背景：** 某市政项目，电气专业设计不提供纵断面图纸，但甲方需要电气专业Revit模型。

- **难点**：仅有道路中心线纵断面图和电气专业管线平面图；路面存在多个坡度，电气节点与道路桩号不同步，无法简单用道路中心线数据推算，只能将道路平面线投影到路面来取得数据。

- **传统手动建模方式**：基本无解。
- **Dynamo/编程方式**：暂时能想到的以下2种实现方式，保守估计均需要 **1~2天**，对于BIM工程师的综合技能要求都不低。
- 方式1.在已有道路模型的B平台投影绘制电气专业管线路径的空间线，拿到空间线后，在Dynamo编写脚本生成电气管线。
- 方式2.完全在Revit进行，导入B平台道路模型(DWG格式)，由于是三角面模型无法直接投影；编写Dynamo程序获取模型三角面顶点，编写顶点去重脚本，通过去重后的点生成地形，再将电气管线平面节点投影至地形，取得数据生成电气管线。
- **本工作流方案**：通过自然语言描述规则，AI自动执行。描述需求生成地形模型，总计耗时 **5分钟**（3w+点数据量较大） ；描述需求投影取得空间线，总计耗时 **3分钟** ；描述需求按中心线生成电气管线，总计耗时 **3分钟** 。

### 案例三：固化团队“专家经验”

> **背景：** BIM团队中熟练掌握Revit API和Dynamo的人很少，遇到复杂任务只能等待核心成员处理，形成效率瓶颈。

- **传统方式**：依赖有开发能力的核心成员手工/AI辅助，编写代码或Dynamo脚本。
- **本工作流方案**：将核心成员的经验和“踩坑”记录，并固化为`Rules`（规则），且规则能随时间日益完善沉淀，让AI自动遵循最佳实践。团队成员只需清晰描述需求，即可调用“Revit专家级二开”的AI能力。

> **核心价值总结：** 这套工作流的核心，不在于“让Revit变快”，而在于 **“让以前做不到/难以完成的事变得可以做”**，降低开发门槛，解放生产力。

## 核心资产：Rules（规则）

`rules/revit-global rules.md` 是本项目 **最具价值的核心资产**。不仅是代码规范，更是一套经过多次实战踩坑后总结的 **AI 编码强制行为准则**（持续完善中）。

### 它解决了哪些关键问题（举例）？

| 问题 | 解决方案 |
| :--- | :--- |
| **防止 AI 瞎猜参数名** | 强制要求先询问用户，禁止硬编码参数名。 |
| **超时诊断流程** | 当 Revit 卡顿时，提供标准化的多级诊断决策树，不再盲目等待或重试。 |
| **代码安全模板** | 强制 `try-catch`、单一弹窗输出、事务管理规范，避免数据丢失风险。 |
| **杜绝常见编译错误** | 如 `doc` 与 `document` 变量名冲突、`StringBuilder` 命名空间缺失、PascalCase 变量遮蔽等。 |

> 拥有这套 Rules，相当于给 AI 配了一个"Revit API 资深导师"。它让 AI 的输出质量从一个"实习生"水平，提升到"有多年经验的 Revit 二次开发工程师"水平。

## 快速开始（精简版）

### 前置条件

- Revit 2020 或更高版本
- VS Code
- Node.js（用于运行 MCP Server）

### 安装步骤

```bash
# 1. 安装 Revit 插件
# 下载 mcp-servers-for-revit，将 .addin 文件放置于 Revit Addins 目录

# 2. 安装 MCP Server
npm install -g mcp-server-for-revit

# 3. 配置 VS Code + Cline
# 安装 Cline 扩展，配置 DeepSeek（或其他兼容大模型）的 API Key
```

### 启动与使用

1. **启动服务**：在 Revit 中点击 **Revit MCP Switch** 启动服务。
2. **打开 VS Code** 并激活 Cline 扩展。
3. **开始对话**：在 Cline 中输入你的第一个指令，例如：
   - "帮我统计当前项目中所有墙的类型及数量"
   - "测试弹出对话框，内容Hello Revit！"
   - "高亮显示当前视图中所有高度大于2米的结构柱实例"

> 详细的图文配置步骤请查看 `docs/installation.md`（持续完善中）。

## 能力边界（三个天花板）

在开始使用前，请务必了解这套工作流 **不能做什么**，以免产生不切实际的预期：

| 天花板 | 说明 |
| :--- | :--- |
| **不能一句话翻模** | 受限于 Revit 的内建类别体系，**无法像在 Blender 中一样生成任意几何体**。AI 只能操作 Revit 已有的类别和参数，无法凭空创造新的几何类型。 |
| **不能执行超复杂单步操作** | 受限于 Revit 的"单次外部事件"机制，**极其复杂的任务需拆分为多个子任务**。例如"翻模一整栋楼"需要分解为"生成轴网 -> 生成标高 -> 生成墙 -> 生成楼板..."等多个步骤。 |
| **不能精准理解模糊描述** | AI 的推理依赖于精确的指令。**可以执行：** "把 Structural 参数改为 true"；**可能无法准确执行：** "让这面墙变成承重墙"这种模糊表达。 |

> **建议：** 将复杂任务拆解为多个清晰的子任务，逐步与 AI 对话完成。每个子任务聚焦于一个明确的目标。
